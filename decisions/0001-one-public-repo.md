# 0001: コードは公開リポジトリ english-trainer 1 つに置き、画面は GitHub Actions で作って Pages に出す

日付: 2026-10-30
状態: 有効(2026-10-30 本人決定)
出典: 本人との相談(2026-10-30)、hub#0002(5 つとも Wellness app と同じ開発環境にそろえる)

## 文脈

手元の `C:\English` は git に入っていなかった。公開リポジトリ `english-trainer` には、`tools/build_pwa.py` で作った完成品(`pwa/` の 6 ファイル)だけを、ブラウザから手でアップロードしていた。GitHub Pages は無料プランでは公開リポジトリでしか使えない。

アプリに秘密や外部への通信は無い。学習の記録は端末のブラウザの中だけにある。

## 決定

1. コード一式(`app/`・`tools/`・`pwa/` の手で作るファイル・指示文・お題・フレーズ集・文書)を `english-trainer`(公開)に置く
2. `pwa/index.html` は commit しない。GitHub Actions が `tools/build_pwa.py` で作り、Pages に出す
3. 学習の記録(`logs/`)は commit しない。`.gitignore` と commit 前の検査で止める

## 理由

- 公開されて困るものがコードの中に無い。困りうるのは学習の記録だけで、それは機械で止められる
- リポジトリが 1 つで済み、手でのアップロードが無くなる。公開リポジトリは Actions が無料で、鍵の管理も要らない

## 捨てた案

- **非公開(コード)と公開(完成品)の 2 つに分ける**: 指示文などを隠せるが、完成品を送るための GitHub の鍵を Actions の秘密の設定に置いて管理し続けることになる。動く部品が増える
- **今のまま手でアップロード**: 何を出したかが記録に残らず、検査も通らない

## 影響

- ChatGPT 用の指示文、お題の一覧、フレーズ集、README の目標も公開される。本人の生活の具体や学習の記録は、文書にもコードにも書かない
- Pages の公開元を「main の直下」から「GitHub Actions」に切り替える(リポジトリの設定)
- 見直す条件: 公開したくない教材や記録をリポジトリに置く必要が出たとき
